RabbitLock's roadmap applies one policy through each platform's own credential feature, where one exists. Before building those adapters, we checked every candidate against the vendor's documentation and, where we could, by hand. Adapters are **not shipped**; see the [roadmap](/roadmap).

For every platform we asked:

- **Configurable:** can a tool create, change and delete the secret *and* the hosts it may reach, from a file, CLI or API?
- **Hidden:** does the agent get a placeholder instead of the real value?
- **Logged:** is each use of a credential recorded somewhere a tool can read?
- **Approval:** can a single use wait for a person?

## Results

| Platform | How it's configured | Configurable | Hidden from agent | Per-use log | Per-use approval | Maturity |
| --- | --- | --- | --- | --- | --- | --- |
| **Claude Code CLI (local)** | Settings file: `sandbox.credentials.envVars[]` with `mode: "mask"` and `injectHosts`, plus `sandbox.network` | **Yes**, tested | **Yes**, tested on macOS | No | No (per tool call only, via hooks) | Masking needs experimental `tlsTerminate` |
| **Codex CLI (local)** | `config.toml`: `[permissions.<profile>.network.mitm]` hooks with `inject_request_headers` | **Yes**, tested | **Yes**, tested | Partial (proxy events record host and method, not the secret) | Per host, on allowlist misses only | Experimental, not in official docs |
| **Claude Managed Agents** | REST: `/v1/vaults/{id}/credentials`, with `networking.allowed_hosts` | **Yes** | Yes | No | No (per tool call: `always_ask`) | Beta |

## What this means

**Enough platforms can be driven.** Five can be configured end to end, secret and hosts, from a file or an API: Claude Code CLI, Codex CLI, Claude Managed Agents, the OpenAI Agents API and Daytona. Docker Sandboxes adds a sixth through its CLI. The roadmap's bar was three, so adapters go ahead.

**No platform records each use of a credential, or lets an outside approver hold one.** Approvals exist only per tool call or per host, and logs record configuration changes, not uses. So:

- Through a platform's built-in feature, RabbitLock can deliver **one policy everywhere and detect drift**, and record what it configured, where and when.
- **Per-use approvals and per-use receipts need RabbitLock's own proxy.** That stays true until platforms add a hook for them.

**First-party cloud agents can't be driven at all.** Claude Code on the web and Codex cloud keep values hidden but are configured only in their UIs. Copilot, Cursor and Devin have APIs but hand the agent the real value, so the policy can set their secrets but can't keep them from the agent.

**Nobody scrubs responses but Daytona.** In our Claude Code test, an allowed host that echoed the token put the real value back in the agent's context. RabbitLock's proxy has the same gap today ([limits](/reference/limits)).

## First adapters

In order:

1. **Claude Code CLI**: write `sandbox.credentials` and `sandbox.network` from the policy, then launch `claude` with `--settings`.
2. **Codex CLI**: write the `network.mitm` hooks into a Codex profile. It is experimental, so pin versions and re-test each release; Codex has reserved a `credentials` section that may replace it.
3. **Claude Managed Agents**: create and rotate vault credentials with `allowed_hosts` from the policy.

Next: Daytona, the OpenAI Agents API and Docker Sandboxes.

## How we tested

- **Claude Code 2.1.331 on macOS.** A throwaway token with `mode: "mask"` was allowed to reach `httpbin.org`.
  - In the agent's shell, the variable held a `fake_value_<uuid>` placeholder.
  - httpbin received the real value.
  - A second allowed host that wasn't in `injectHosts` received the placeholder.
  - A host not on the allowlist was blocked and reported as a sandbox violation.
  - The agent's attempt to widen the allowlist was refused under `strictAllowlist`.
- **Codex CLI 0.171.0.** `codex sandbox -- curl` ran with a dummy value and a `network.mitm` hook for one host.
  - Requests carrying the placeholder header reached httpbin with the dummy value.
  - Requests without the placeholder were refused, as were unhooked paths and other hosts.
- **Everything else** comes from vendor documentation only. The cloud platforms need accounts we didn't create for this check.
