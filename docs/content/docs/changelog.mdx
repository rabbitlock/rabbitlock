## 0.3.0 (2026-11-24)

- Agent-led setup: [rabbitlock.com/agents.md](https://rabbitlock.com/agents.md) and a Claude Code plugin (`/plugin install rabbitlock --marketplace rabbitlock/rabbitlock`). See [Set up with your agent](/guides/agent-setup).
- `rabbitlock status [--json]`: setup state and next steps, and lets an agent check whether it's running under RabbitLock
- `rabbitlock import .env`: encrypt an existing `.env` in one step
- `rabbitlock init --agents-md`: instructions for coding agents in `AGENTS.md`
- `rabbitlock run` warns when a `.env` file next to the policy still holds a brokered secret's real value
- `RABBITLOCK_SANDBOX` in the agent's environment

## 0.2.0 (2026-11-24)

- `rabbitlock set NAME --generate`: creates a random secret and hands it to you (`--reveal`, `--to-command`) or to nobody (`--no-handoff`), so an agent can set up accounts and services with a credential it never sees. See [Let your agent set up accounts](/guides/provisioning).
- `generated` receipts

## 0.1.0 (2026-11-23)

First public release of the `rabbitlock` CLI.

- Placeholders for secrets, swapped in only on outbound HTTPS to per-secret allowed hosts
- Injection into headers (including Basic auth), URLs, and JSON, form and text bodies up to 1 MiB
- Human approvals (`once`, `every`) through OS dialogs
- Receipts in `.rabbitlock/receipts.jsonl`, never containing values
- Agent sandbox by default: `sandbox-exec` on macOS, `bwrap` on Linux, Claude Code's own sandbox for `claude`
- Encrypted secrets in git (SOPS format, hybrid X25519 + ML-KEM-768 recipients), shareable with teammates
- `rabbitlock ca trust` for Go tools on macOS
