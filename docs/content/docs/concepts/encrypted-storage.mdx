---
title: Encrypted storage
description: Where your secrets are stored, how they're encrypted, and who can decrypt them.
---

Secrets live in a SOPS-format JSON file. Where it lives depends on the project's mode:

| Mode | Location | Who can decrypt |
| --- | --- | --- |
| **Individual** (default) | `~/.rabbitlock/projects/<project>/secrets.sops.json`, outside the repo | Only you |
| **Team** (`rabbitlock team enable`) | `secrets.sops.json` in the repo, committed | Every recipient listed in the policy |

- **Encryption:** secret values are encrypted with a random data key. The data key is encrypted separately for each recipient using hybrid post-quantum encryption, which combines **X25519 and ML-KEM-768**. It is designed so that an attacker has to break both.
- **Integrity:** the file carries a MAC. RabbitLock verifies it on every read, and a tampered file stops the run.
- **Your key:** a 32-byte seed in `~/.rabbitlock/identity` (owner-only permissions) derives your hybrid keypair. It never leaves your machine and is never sent to RabbitLock.
- **The file holds a flat set of `NAME: value` pairs.** Only names that also appear in the policy are given to agents.

```bash
rabbitlock set NAME     # add or update (value from stdin, or a hidden prompt)
rabbitlock rm NAME      # remove
rabbitlock ls           # names and their policy, never values
```

Every change re-encrypts the file. In team mode it's encrypted for every recipient in the policy, and your own key is always included. See [Teams](/guides/teams).

<Callout type="warn" title="Back up your identity">
If you lose `~/.rabbitlock/identity` and nobody else is a recipient, the secrets can't be recovered. Re-create them from their source.
</Callout>
